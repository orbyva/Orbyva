# 049 — Atalho de controle de medicações

## Contexto
Hoje criar um lembrete de remédio recorrente exige passar pelo form completo de tarefa (`TaskFormFields.tsx`, abas Geral/Data e repetição/Organização/Registros) e montar a recorrência manualmente em `TaskRecurrenceField.tsx`. O pedido é um atalho: um form pequeno e específico (nome do remédio, horário, frequência) que, por baixo, cria uma tarefa recorrente comum usando a engine de recorrência que já existe (`domain/tasks/recurrence.ts`, `RecurrenceRule` com `frequency: "daily"` e `interval`) — sem reinventar cálculo de datas. A materialização das ocorrências futuras (`materializeRecurringInstances`, `api/tasks/tasks.ts:12-58`) já roda no `fetchTasks()` e já respeita `due_time`, então "criar já no calendário" não pede nada novo além de popular os campos certos.

A segunda parte do pedido — salvar o horário em que a dose foi de fato tomada — já tem onde morar: `updateTask` (`api/tasks/tasks.ts:168-190`) grava `completed_at = new Date().toISOString()` sempre que `status` vira `"done"`, e esse valor já é a data/hora real de quando a pessoa marcou a tarefa como concluída (não o horário agendado em `due_time`). `TaskQuickFields.tsx:83-84` já exibe "Concluída em {completed_at}" pra qualquer tarefa concluída — pra medicação isso é literalmente "tomado às", sem precisar de coluna nova. O que falta é (a) marcar que uma tarefa/série é uma medicação, pra poder filtrar/agrupar o histórico e diferenciar a exibição, e (b) uma visualização do histórico de doses de uma série.

Não há feature em `done/`/`todo`/`in-progress` que cubra "atalho de criação especializado" — não existe esse padrão no projeto ainda (só o form genérico de tarefa). A mais próxima em espírito é `done/028` (excluir todas as ocorrências de uma recorrência), que esta feature reaproveita sem alterar.

## Decisões
- **Sem engine de recorrência nova**: o atalho só monta um `RecurrenceRule` (`frequency: "daily"`, `interval: 1` para "diária" ou `interval: N` para "a cada N dias") e chama `createTask` — a tarefa criada é uma tarefa recorrente comum em todos os sentidos (materialização, edição, agenda, gantt, kanban).
- **Flag `task.is_medication` (boolean, default `false`)**: novo campo, mesmo padrão de `is_milestone` (feature 037/`20260814020000_task_milestone.sql`). Marca a tarefa-origem e precisa ser propagado por `materializeRecurringInstances` pra cada ocorrência materializada (hoje essa função só copia um subconjunto de campos do template — `icon_key`/`icon_url`/`priority` também não propagam, isso já é assim antes desta feature e não é escopo daqui, mas `is_medication` precisa propagar porque o histórico de doses depende dele por ocorrência).
- **"Horário tomado" = `completed_at`, sem coluna nova**: `completed_at` já é a data/hora real de quando o `status` virou `"done"` (não o horário agendado). Reaproveitar em vez de duplicar evita duas fontes de verdade pro mesmo instante. Não há, no app, nenhum mecanismo hoje de "corrigir manualmente" um `completed_at` pra nenhum tipo de tarefa — não introduzir esse mecanismo só pra medicação nesta rodada (ficaria inconsistente com todo o resto). Se aparecer a necessidade real (ex.: registrar retroativamente uma dose esquecida), é uma feature própria depois.
- **Dose "atrasada"**: novo helper puro `isDoseLate(task, graceMinutes = 60)` em `domain/tasks/medication.ts` — compara `completed_at` contra `due_date` + `due_time` agendados, com margem de tolerância de 60 min antes de marcar como atrasada (evita falso positivo por diferença de poucos minutos entre o alarme e o clique). `false` sem `completed_at`, sem `due_date`, ou fora do escopo de medicação. Usado só pra exibir um badge no histórico — não bloqueia nem impede marcar concluída fora do horário, que continua funcionando exatamente como qualquer outra tarefa hoje.
- **Curso com fim definido (ex.: antibiótico por 7 dias) não é campo do atalho**: o atalho cobre só o pedido literal (nome, horário, frequência). Quem quiser uma medicação com fim programado edita a tarefa criada normalmente — `TaskRecurrenceField.tsx` já expõe "Termina: em uma data / depois de N ocorrências" pra qualquer recorrência simples, medicação incluída, sem precisar de UI extra no atalho.
- **Exclusão de série**: nenhuma mudança em `TaskDeleteDialog.tsx`/`isSimpleRecurringTask`/`deleteTasks` (feature 028) — uma tarefa de medicação é `recurrence_rule`/`recurrence_origin_id` sem `linked_recurring_id`, logo já cai no caminho de "recorrência simples" e já ganha as opções "Excluir somente esta"/"Excluir todas as ocorrências" sem código novo.
- **Edição da tarefa-origem** (mudar horário/frequência depois de criada): mesma semântica que qualquer recorrência simples hoje — só afeta ocorrências futuras ainda não materializadas; ocorrências já materializadas não são recalculadas retroativamente. Comportamento pré-existente do sistema de recorrência, não redesenhado aqui.
- **Histórico de doses reaproveita o dialog "Ocorrências de..." existente** (`TaskList.tsx`/`ProjectDetail.tsx`, populado via `findSeriesTasks`) em vez de um componente novo — quando a ocorrência pertence a uma série de medicação (`t.is_medication`) e está `done`, a linha troca o horário agendado por "Tomado às {completed_at}" (+ badge "Atrasada" quando `isDoseLate`); ocorrências não concluídas continuam mostrando o horário agendado como hoje. Séries que não são de medicação não mudam em nada.
- **Atalho vive só em `TaskList.tsx`** (botão "Nova medicação" ao lado de "Nova tarefa", ambas as posições do header), não em `ProjectDetail.tsx` — medicação é gestão pessoal, não trabalho de projeto. Uma medicação pode acabar associada a um projeto depois (edição manual), o que não quebra nada, só não é o fluxo de entrada.
- **Sem componente novo para o form**: `MedicationQuickCreateDialog.tsx` é um dialog próprio e pequeno (3 campos: nome, horário, frequência), não uma variante de `TaskFormFields` — o form completo continua disponível via "Editar" na tarefa criada, pra quem precisar de tags/prioridade/ícone/etc. depois.

## Notas
- Bug real encontrado e corrigido durante o desenvolvimento: o input de "A cada quantos dias" clampava o valor (`Math.max(1, ...)`) a cada tecla digitada, então limpar o campo pra digitar outro número fazia o valor saltar de volta pro mínimo antes do próximo dígito ser inserido (ex.: apagar "2" e digitar "3" resultava em "13", não "3"). Corrigido guardando o valor como string bruta no estado e só convertendo/clampando em `handleSave`.
- `npm run test` completo tem 2 falhas pré-existentes e não relacionadas a esta feature, em `src/lib/__tests__/currency.test.ts` (`formatDateBR`/`formatDateTimeBR` retornam `"·"` no código-fonte, mas o teste espera `"—"`) — confirmado que `src/lib/currency.ts` não foi tocado nesta sessão (sem diff) e a falha reproduz isoladamente rodando só esse arquivo de teste. Não é escopo desta feature; fica registrado aqui pra quem for mexer em `currency.ts` depois.
- "Horário tomado" no dialog de ocorrências mostra só a hora (`formatTimeOfDay`, reaproveitado de `TimeEntryRow.tsx`), não data+hora — mais fiel ao pedido original ("salvar o horário") que o `formatDateTimeBR(completed_at)` citado na tarefa, que (sem o segundo argumento) formata só a data, sem hora nenhuma.

# 066 — Item de compras sem categoria

## Contexto

Hoje é impossível anotar "pilha AA" na lista sem antes inventar uma categoria para ela. A obrigatoriedade está cravada em três camadas: `shopping_item.shopping_category_id` é `not null` no banco (050), o `ShoppingItemDialog` só habilita o botão salvar com `form.shopping_category_id` preenchido, e o botão "Novo item" da página fica `disabled` enquanto `categories.length === 0`, com um `EmptyState` mandando criar categoria primeiro. Isso inverte o custo do fluxo mais frequente de uma lista de compras — a captura rápida de uma coisa que acabou — e é exatamente o que o prompt pede para desfazer: categoria passa a ser organização opcional, não pedágio de entrada.

## Decisões

- **`shopping_item.shopping_category_id` vira nullable**, em migration nova (`alter column ... drop not null`), e não editando `20260816130000_shopping_list.sql`. A migration da 050 já foi verificada em Postgres descartável e está na fila de `supabase db push` do usuário; reescrevê-la faria a verificação já feita descrever um arquivo que não existe mais, e quebraria o bookkeeping do CLI se ela já tiver sido aplicada em qualquer ambiente.
  - **Descartado — categoria implícita "Sem categoria" como linha real no banco**: exigiria semear uma linha por usuário, ela apareceria nos pickers como se fosse editável, e abriria a pergunta sem resposta boa "posso renomear/apagar essa categoria?". O dado real aqui é *ausência* de categoria, e `null` é como se escreve ausência.
- **`on delete cascade` da categoria continua como está.** Apagar uma categoria continua apagando os itens dela, com o `ConfirmDeleteDialog` avisando quantos ("N itens dela também serão excluídos") — é consentimento informado, decisão explícita da 050, e não é o que o prompt pede para mudar.
  - **Descartado — trocar para `on delete set null`**: transformaria "apaguei a categoria da obra" em "a lista da casa encheu de itens soltos que eu achava que tinham sumido", uma perda de contexto silenciosa. Se o usuário pedir depois, vira feature própria (com escolha no diálogo entre apagar junto e soltar os itens).
- **Item sem categoria aparece num pseudo-grupo "Sem categoria", sempre por último**, depois das categorias reais. Ele **só existe quando tem item** — ao contrário das categorias reais, que aparecem vazias de propósito (a categoria vazia é uma intenção do usuário; o grupo sem categoria é só um resto). Ele não tem cor, não tem botão de editar e não tem botão de excluir: não é uma categoria.
- **O grupo "Sem categoria" não aparece quando há filtro de projeto ativo.** O vínculo com projeto é da categoria, nunca do item (decisão da 052) — logo um item sem categoria não pertence a projeto nenhum e não pode aparecer no recorte de nenhum. Pela mesma razão, `ProjectShoppingSection` na página do projeto não muda em nada.
- **No formulário, "Categoria" deixa de ser obrigatória e ganha a opção explícita "Sem categoria"**, com valor sentinela (`__none__`), porque o `Select` do Radix não aceita `value=""` — é o mesmo recurso que `ShoppingList` já usa em `ALL_PROJECTS = "__all__"` e que o `ProjectPicker` usa em "Sem projeto". `canSave` passa a exigir só o título.
- **A pré-seleção de categoria ao abrir o diálogo muda**: pelo botão geral "Novo item", o padrão passa a ser "Sem categoria"; pelo botão "Adicionar item em X" do cabeçalho de uma categoria, o padrão continua sendo X. Hoje o padrão é `categories[0]`, o que arquiva silenciosamente o item na primeira categoria da ordem alfabética — um erro difícil de perceber, e que só existia porque o campo era obrigatório.
- **"Novo item" nunca mais fica desabilitado.** O `EmptyState` de lista totalmente vazia passa a oferecer as duas ações lado a lado ("Novo item" e "Nova categoria"), com a categoria descrita como o que é: opcional.
- **Criar tarefa a partir de um item sem categoria continua funcionando** — `buildTaskDraftFromItem` já trata a ausência (descrição fica só "Lista de Compras", sem o sufixo da categoria) e `createTaskFromShoppingItem` já guarda o `if (item.shopping_category_id)`. Isso passa a ser um caminho real e ganha teste, em vez de continuar sendo defesa acidental.
